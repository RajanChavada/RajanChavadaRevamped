# How I Use AI as a Developer

Everyone wants to use AI. Generate applications in minutes by throwing prompts into Cursor, Claude Code, ChatGPT, or Gemini and expect an AI SaaS B2B startup to materialize in front of them.

**"Vibe coding"** is letting developers like me — and you — code and iterate at the speed of a whole team. But with all these new tools, people fall into the trap of writing *"do it for me"* and praying it passes the tests, then pushing slop into production and wondering why their GPT wrapper isn't wrapping.

I've built patent-pending agentic systems deployed to thousands of users in regulated financial environments at RBC. I've shipped AI tools that actually work. And I've learned this:

> **AI doesn't replace engineering, it amplifies it** — but only if you know how to use it properly.

---

## The Problem

Picture this. You go on LinkedIn and see that someone built another AI startup, so you load up VSCode and... *blank*. You don't know what to make or how to make it.

Let's say you do know what to make — you've discovered a niche and know exactly how you're going to disrupt the market. **So where do you start?**

LLMs are not a black box that can ship your product. You can't always `ctrl+c` / `ctrl+v` and deploy. Understanding backend and frontend architecture as a developer is **mandatory**, as is understanding the design patterns and complex architecture of a real application.

---

## Phase 1: Accelerated Learning

### The Researchers

Before I write a line of code, I research. I jump between tools for different perspectives because variety gives me the spark I need instead of conforming to any single model's output:

- **ChatGPT**
- **Comet**
- **Gemini**
- **NotebookLM**
- **Deepseek**

Simple prompts produce massive results.

**Step 1: Explain it like I'm 5, then show me production code.**

```text
Explain WebSocket connection pooling for real-time trading like I'm 5,
then show me a production Python example.
```

That snippet stays in your brain and compounds over time.

**Step 2: Summarize what you're too lazy to read.**

Found an interesting article but don't have 20 minutes?

```text
Summarize this article about distributed caching.
Give me key takeaways in bullet points.
```

## Phase 2: Context Engineering

When I develop with agentic tools like **Cursor**, **Claude Code**, or **Windsurf**, I create a `/docs` folder that houses all my context files as markdown. Think of these files as machine-interpretable configuration — a README for agents, not humans.

### Separation of Concerns

Each `.md` file in `/docs` represents a different layer of the application: architecture, API contracts, briefing files, workflows, conventions. Agents work better when they're focused on one task at a time with clear instructions.

### Why Markdown?

Markdown's structure (headers, lists, code blocks, examples) makes it easy for LLMs to extract step-by-step instructions without hallucinating. You're giving the agent a **map** instead of vague directions.

| Benefit | Description |
|---------|-------------|
| **RAG-friendly** | Feeding markdown into the agent's context window (via tools like `@docs` in Cursor) lets the LLM locate relevant sections quickly. |
| **Version-controlled** | Markdown evolves with the repo. You can track changes, revert bad ones, and maintain clear architectural decisions. |

### Core Context Files

**ARCHITECTURE.md**

- High-level system diagram (components of the system you want to build)
- Data flow (how information moves)
- External dependencies (APIs, databases, third-party services)
- Non-functional requirements (performance, scaling, caching)

**CONVENTIONS.md**

- Code style (error handling patterns, naming conventions)
- File structure (where services, models, and tests live)
- One-shot examples (show the agent what "good code" looks like)

**MVP_BRIEF.md**

- Product vision (what problem are we solving?)
- Core features (scope for the MVP)
- Success metrics (how do we measure impact?)

**MVP_PLAN.md**

- Feature roadmap (build order, dependencies)
- API contracts (endpoints, request/response shapes)
- Database schema details
- Authentication flow

**WORKFLOWS.md**

- Development process (how to add a new feature)
- Testing workflow (when to write tests, how to run them)
- Deployment steps (even if just "run locally" for the MVP)

**GETTING_STARTED.md**

- Setup instructions (install deps, env vars, run commands)
- Common tasks (add an endpoint, run migrations, debug)

**QUICK_REFERENCE.md**

- Key commands (start server, run tests, format code)
- Useful snippets (common patterns, utility functions)

### Example ARCHITECTURE.md

Here's a condensed `ARCHITECTURE.md` I wrote for a recruiter outreach app — using Gemini to build unique profiles for "standout" cold emails:

```markdown
# Recruiter Outreach Personalization Platform - Architecture

## Overview

**Purpose**: Automate personalized recruiter outreach by enriching
LinkedIn profiles with Gemini 3 Vision, then generating tailored
emails via LLM.

**Key Insight**: Gemini 3 Vision acts as an "intelligent scraper" that
understands LinkedIn profile context (hobbies, interests, values)
holistically — replacing brittle CSS selectors.

## High-Level Data Flow

LinkedIn Profile URL (user input)
         ↓
  [Playwright Scraper]
    - Screenshot profile
    - Fetch HTML content
         ↓
  [Gemini 3 Vision Agent]
    - Analyze screenshot + HTML
    - Extract: name, role/company, outreach hooks
         ↓
  [Structured JSON Output]
         ↓
  [Store in PostgreSQL (JSONB columns)]
         ↓
  [Email Generator Service]
    - Use enriched profile data
    - Call Gemini 3 Pro (text) with personalization context
         ↓
  [Generated Email]
         ↓
  [Frontend Display]
    - Show recruiter profile + generated email
    - Allow manual editing

## Technology Stack

| Layer     | Tech                 | Why                                    |
|-----------|----------------------|----------------------------------------|
| Backend   | FastAPI + asyncio    | Fast MVP, native async for I/O         |
| Scraping  | Playwright           | 40% faster than Selenium, native async |
| Vision AI | Gemini 3 Pro Vision  | Multimodal, context-aware, free tier   |
| Database  | PostgreSQL           | JSONB for enriched data                |
| Frontend  | React + Vite         | Fast, simple state management          |
```

### How It Works

You prompt the agent with:

```text
Using ARCHITECTURE.md, implement the Playwright scraper service.
Follow the error handling strategy in the Scraper Layer section.
```

And the agent knows exactly what to build — the technology stack to scaffold against, plus unit testing, error handling, and table schema architecture.

## Phase 3: Burst Development

After I've created the folder housing all the markdown files, I begin what I call **Burst Development** — building features of the architecture in phases with small, testable milestones instead of trying to get all the code out in one shot.

For each roadmapped feature, the workflow is:

1. **Prompt** with the roadmap context using `ARCHITECTURE.md`.
2. **Include** all necessary requirements and logic.
3. **Review and test** the generated code against your entire context, and validate manually by exercising the feature.
4. **Iterate** until it works and passes all tests.
5. **Maintain** a `MEMORY.md` to avoid context rot, where agents begin to "forget" earlier decisions.

### Example MEMORY.md

```markdown
# Project Memory

## Recent Changes (Dec 21, 2024)
- Implemented Gemini Vision agent in `agents/gemini_vision.py`
- Added retry logic with exponential backoff (1s, 2s, 4s max)
- Confidence scoring: 0.0 if field is missing, 0.5-1.0 based on clarity
- Mock tests in `tests/test_gemini_agent.py` (no live API calls in CI)

## Known Issues
- Private LinkedIn profiles return 403 — need fallback message
- Gemini occasionally returns nested JSON — add flattening logic

## Next Steps
- Implement database layer (Phase 3)
- Test vision agent on 50 real profiles before moving on
```

## Phase 4: Advanced Workflows — Specialized Tools

Not all development should happen inside Cursor. I leverage **specialized tools** for specific parts of the software journey.

### Frontend Design: Figma AI + v0 by Vercel

**Use case:** You need UI mockups and React components fast.

1. Describe your UI to Figma AI or sketch it manually.
2. Export as PNG or share the Figma link.
3. Feed it into v0 by Vercel: *"Convert this design to React + Tailwind."*
4. Get production-ready component code in seconds.

### Database Schema: ChatGPT + SQL

**Use case:** You need an optimized database schema.

```text
I'm building a recruiter outreach platform. I need a PostgreSQL schema for:
- Storing LinkedIn profile data (name, role, company, bio, hobbies)
- Storing generated emails (subject, body, sent status)
- Tracking which profiles have been processed

Requirements:
- Use JSONB for flexible profile data
- Add indexes for fast lookups by LinkedIn URL
- Include timestamps for created_at, updated_at
```

ChatGPT generates the schema. You review, refine, and add it to `ARCHITECTURE.md`.

### Infrastructure: Terraform + Claude

**Use case:** You need to deploy to AWS or GCP.

```text
Using Terraform, create infrastructure for:
- FastAPI backend on AWS ECS (Fargate)
- PostgreSQL RDS instance
- S3 bucket for Playwright screenshots
- CloudFront CDN for React frontend

Include security groups, IAM roles, and environment variables.
```

Claude generates the IaC. You review, test locally with `terraform plan`, then deploy.

### Learning & Research: NotebookLM

**Use case:** You need to understand a complex topic fast — distributed systems, Kafka, Kubernetes.

1. Upload PDFs, articles, or docs to NotebookLM.
2. Ask: *"Summarize the key concepts of Kafka pub/sub in five bullet points."*
3. Generate study guides, flashcards, or even AI-generated podcasts.

**Example:** Upload AWS CloudFormation docs, ask *"How do I set up auto-scaling for ECS with CloudFormation?"*, and get a curated, context-aware answer.

## Conclusion

This phase-based workflow won't just make development easier with emerging AI tools — it will make you more **versed** in using them. Only a small percentage of developers know how to architect systems with proper validation and context.

Following these steps will make you a more confident developer, keep you ahead of current AI trends, and — hopefully — land you that internship or role you've been chasing.
